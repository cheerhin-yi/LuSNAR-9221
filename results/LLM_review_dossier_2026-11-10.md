## 0. 一页摘要（先读这里）

1. **比赛**：MoonSeg AI Challenge 2026。截止时间 **2026-11-20 23:59（Asia/Shanghai）**，**只能提交一次**。评分 **S = (m2 + m4 + 2·m9) / 4**，其中 m2、m4、m9 分别是 Moon_2、Moon_4、Moon_9 三个场景的 mIoU。官方基线 **S = 0.8046**。
2. **现有主模型**：SegFormer-B2 + V_B1C + ROW + BLV。crop 512，batch 48/卡，2 卡 DDP，bf16，lr 6e-5，训练 20k iter。在 Scene5 上选出 best.pth（iter 17000），Scene5 mIoU 0.8719。
3. **推理方案选择**：先在 Scene5 上做（A 半集选型，B 半集只报一次），胜出的是 P1P2（logit 偏置 + 几何连通域规则），B 半集 0.8905。但换到开源的 Moon_2/4/9 上，P1P2 反而最差（S 0.8254）。在 Moon_2/4/9 上最好的是 I1a（每个类别各自取最佳尺度），**S = 0.8369（+0.0323）**。比赛线目前选 I1a。
4. **需要评审重点关注的反常现象**：较早的基线模型 B1（SegFormer-B2 + RCS + mosaic + CC paste + ACW，没有 ROW/BLV/坑增强）在 Scene5 上只有 0.8630，比主模型低。但它在 Moon_2/4/9 上**单尺度、不加 TTA**，换算 S 却是 **0.8571【本文计算】**，**比主模型最好的 0.8369 还高 2 个点**，Moon_9 撞击坑 IoU 是 0.4548（主模型是 0.26–0.31）。这说明 Scene5 上的提升没有迁移到比赛场景，甚至方向相反。这是目前方案最大的疑点（详见 §3.6、§6）。
5. **论文线**：完全独立。用 LuSNAR 官方论文划分（训练 Moon_1/2/4/6/8/9，测试 Moon_3/5/7，论文中 SegFormer 基线 89.96% mIoU），所有实验重新做，推理方式也重新选。比赛结果只作为单独的第二组证据。
6. **正在运行**：plus5（同一配方，把 Scene5 也加进训练，Moon_1/3/5/6/7/8 共 8002 张，不做验证，用 last.pth）。2026-11-10 13:47 开始，预计 **2026-11-11 08:50 左右** 结束（按约 3.4 s/iter 估算）。

### 3.1 模型与配方

| 组件 | 说明（来自 `tools/portable/_lusnar_common.py` 的定义） |
|---|---|
| 主干 | SegFormer-B2（MiT-B2，ImageNet 预训练 `mit_b2_20220624-66e8bf70.pth`），MLP 解码头 |

| 损失 | CE + dice（日志中有 ce/dice 两项） |
| 主配方超参 | crop 512，batch 48/卡 × 2 卡 DDP，bf16，lr 6e-5，20k iter，每 1000 iter 在 Scene5 上验证一次，选 best.pth |

### 3.4 Scene5 推理阶段（第一轮 best.pth，只用 Scene5）

协议：Scene5 按 seed 42 分成 A（799 张）和 B（800 张）。**所有方案预先登记**，只在 A 上选型（选型规则：A 上 mIoU 最高，并且岩石、撞击坑相对 C0 的下降不超过 0.01），B 只报一次。与 C0 的配对比较用逐图 mIoU，做 Wilcoxon 检验 + Holm 校正 + bootstrap 95% CI。

**诊断**
- 单尺度全 Scene5 mIoU：×0.5 0.8519 / ×0.75 **0.8694** / ×1.0 0.8449 / ×1.25 0.7876 / ×1.5 0.6692。×1.25 时撞击坑掉到 0.5655。
- 误差归因：岩石漏检的 80% 被判成月壤；撞击坑漏检的 99% 被判成月壤，小块撞击坑召回只有 0.526（大块 0.910）；山体漏检的 93% 被判成岩石。
- GT 连通域尺寸：岩石中位边长 11.4 px，81.6% 小于 32 px；撞击坑中位边长 5.6 px，71.5% 小于 32 px。

P2 几何规则（来自 `lusnar_scene5_protocols.py`）：
- (a) 质心在图像下方 45% 区域、面积小于 5% 的天空连通域，改成周围的多数类；

### 3.6 分析

1. **P1P2 不能迁移**：在 Scene5 上，P1P2 比 C0 高 +2.5 个点（B 半集 0.8905 vs 0.8655）；在 Moon_2/4/9 上，S 却比 C0 低 −0.5 个点（0.8254 vs 0.8300）。下降主要在 Moon_9：规则 (b) 把一部分岩石改成了山体，岩石从 0.776 降到 0.745，山体从 0.723 降到 0.703。手调的几何规则对 Scene5 过拟合了。
2. **I1a 迁移得比较好**：在 Scene5 上 +1.7 个点（B 半集），在 Moon_2/4/9 上 S +0.7 个点。提升主要来自撞击坑（Moon_9 从 0.259 提到 0.310）和山体，代价是岩石下降（总体 0.817 → 0.797）。
3. **核心短板是 Moon_9 的撞击坑**：主模型只有 0.26–0.31，而 B1 是 0.45。Moon_9 在 S 中权重翻倍，所以 Moon_9 的撞击坑一项就足以左右排名。
4. **训练配方本身的迁移性存疑（最重要）**：

   | 模型 | Scene5 | Moon_2/4/9 换算 S |
   |---|---|---|
   | B1 | 0.8630 | 0.8571（单尺度） |
   | ROW+BLV | 0.8719 | 0.8300（TTA）/ 0.8369（I1a） |

   也就是说，Scene5 上 +0.9 个点，到了比赛场景却变成 −2 到 −2.7 个点。可能的原因（**均未验证**）：
   - V_B1C 的撞击坑加权采样，或 BLV，对 Moon_9 那类撞击坑造成了不利影响；
   - ROW 学到了场景特有的行位置先验（Scene5 与 Moon_9 的视角或地平线位置不同）；
   - TTA 本身在 Moon_9 上有害（B1 的结果是单尺度；主模型没有做单尺度的 Moon_2/4/9 评测，**这个对照缺失**）；
   - B1 的训练 batch 和平台与主模型不同（B1 峰值显存 17.96 GB，主模型 36.8 GB），**B1 的具体 batch 设置【未核实】**；
   - 单一验证场景 Scene5 本身代表性不足。
5. 冒烟阶段的结论（ROW+BLV 最好）全部来自 Scene5 子集、单种子、2k iter，而且大部分单模块的 Δ 在噪声带内。所以“ROW+BLV 有效”在比赛场景上**没有得到证实**。

### 4.1 选型规则（2026-11-10 用户决定）

### 4.2 后续计划（按项目计划的顺序）

1. **plus5**（运行中）→ 在 Moon_2/4/9 上评测。
2. **阶段 3 微调**：在第一轮权重 + Scene5 A 上选微调配方，然后冻结，套用到 plus5 权重上。候选：T5（FixRes 式的头部微调）、T1（偏向放大的多尺度）、T2（Lovász/边界/dice 损失）、深度辅助头、T8（层次化多尺度注意力头，Tao et al. 2020，2k–4k iter，并配一个等长继续训练的对照）。**这几项还都没有跑。**
3. **阶段 4 换主干冒烟**：SegFormer-B5（与现有模块完全兼容；20k 时 batch 降到 24/卡）和 Mask2Former（Swin-B，HuggingFace 实现，需要改造成接入 ROW/BLV + 辅助 CE）。两个冒烟各用一张卡并行跑，胜出者跑 20k。依据之一：火星数据集 DepthMars 上，Mask2Former 在岩石和撞击坑上明显强于 SegFormer（撞击坑 34.75 vs 3.86）。
4. **阶段 5/6**：用选中的配方跑长训，再加 2 个种子，然后决定最终的集成/TTA，提交。集成的接受条件：在 Scene5 B 上相对最好的单模型 Δ ≥ +0.005，bootstrap CI 不含 0，岩石和撞击坑的下降都不超过 0.01。
5. **阶段 7 整图线**（`fullimage_compare\`，在 cheerhin 上跑，独立目录）：1024 整图训练，所有裁剪线模块（包括被否掉的）都重新做一遍冒烟。`-EffBatch 4`（梯度累积，lr 不变，在对照组之前就定死）和 M_FADE 都要加入。按项目时间表，这条线大概率排在比赛截止之后。

### 4.3 风险

| 风险 | 说明 |
|---|---|
| 对开发集过拟合 | 在 Moon_2/4/9 上比较的“模型 × 推理方案”组合越多，选中的方案在隐藏测试上的期望得分就越被高估。如果比赛的隐藏测试图和开源 GT 完全一致，那么这就是“在测试集上选型”，存在**合规与伦理风险**（规则原文**【未核实】**是否允许使用开源 GT） |
| Moon_9 撞击坑 | 主模型只有 0.26–0.31，这一项的方差决定排名 |
| Scene5 与比赛场景不一致 | Scene5 上的结论多次在比赛场景上失效或反转（P1P2、ROW+BLV vs B1） |
| 时间 | 只剩 1–3 天缓冲；Windows 训练速度不稳定（1455 错误）；每次 20k 要 12–28 h |
| 统计可靠性 | 单种子；冒烟的噪声带（±0.02）和很多模块的效应量差不多大 |
| 运维 | 只有一次提交机会，提交格式（L 模式 0–4 索引 PNG + zip）已经在 B1 上验证过 |
